useEffect — What Is a Side Effect?

Side effects are operations that reach outside the React render cycle:

  • Fetching data from an API
  • Setting up a subscription or timer
  • Manually changing the DOM
  • Reading from localStorage
effects.jsx
import { useEffect } from 'react';

useEffect(() => {
  // side effect code here
  document.title = `Count: ${count}`;
});

useEffect — Cleanup Function

The cleanup function runs before the next effect and on unmount:

timer.jsx
useEffect(() => {
  const timer = setInterval(() => {
    setSeconds(s => s + 1);
  }, 1000);

  // Cleanup: runs on unmount or before re-running this effect
  return () => clearInterval(timer);
}, []);

Common cleanup scenarios:

  • clearInterval / clearTimeout
  • Unsubscribe from WebSocket or event listener
  • Cancel an in-flight fetch request (AbortController)

useEffect — Common Pitfalls

❌ 1. MISSING DEPENDENCY
pitfalls.jsx
// Bug: effect reads `count` but doesn't
// list it as dependency
useEffect(() => {
  document.title = `Count: ${count}`;
}, []);
// ESLint warns: "missing dependency"
❌ 2. OBJECT/ARRAY AS DEPENDENCY
pitfalls.jsx
// Bug: new object reference every render
// → infinite loop
useEffect(() => { fetchData(filters); }, [filters]);
// where filters = { status: 'active' }
// created in render body
Install eslint-plugin-react-hooks — it catches most of these mistakes.

useEffect — Infinite Loop Trap

❌ INFINITE LOOP
loop-trap.jsx
function Bad() {
  const [data, setData] = useState([]);

  useEffect(() => {
    fetch('/api/items')
      .then(r => r.json())
      .then(items => setData(items)); // re-render
  }); // ← missing dependency array!

  return <div>{data.length} items</div>;
}
✅ FIXED
loop-trap.jsx
// Add empty dependency array
// (fetch once on mount)
useEffect(() => {
  fetch('/api/items')
    .then(r => r.json())
    .then(setData);
}, []);
setState inside an effect with no deps → re-render → effect runs again → setState… forever.

useRef — Two Use Cases

audio-player/src/components/Player.jsx

1. DOM Access

TextInput.jsx
function TextInput() {
  const inputRef = useRef(null);
  return (
    <>
      <input ref={inputRef} />
      <button onClick={() => inputRef.current.focus()}>Focus</button>
    </>
  );
}

2. Mutable Value (no re-render)

renderCount.jsx
const renderCount = useRef(0);
useEffect(() => { renderCount.current += 1; });
// renderCount.current updates
// without triggering re-render
Live demo: audioRef.current.play() / .pause() / .currentTime = ... in Player.jsx. The <audio> element is a native imperative API — React state alone can't call methods on it, so a ref is the only way in.

Controlled Components & Forms

audio-player/src/components/Player.jsx (seek bar, volume slider)
LoginForm.jsx
function LoginForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const handleSubmit = (e) => {
    e.preventDefault(); console.log('Login:', { email, password });
  };
  return (
    <form onSubmit={handleSubmit}>
      <input type="email" value={email} onChange={(e) => setEmail(e.target.value)} />
      <input type="password" value={password} onChange={(e) => setPassword(e.target.value)} />
      <button type="submit">Login</button>
    </form>
  );
}
Controlled component: React state is the "single source of truth" for the input value.

Data Fetching Pattern

audio-player/src/App.jsx
UserList.jsx
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);
  useEffect(() => {
    fetch('/api/users')
      .then(res => { if (!res.ok) throw new Error(`HTTP ${res.status}`); return res.json(); })
      .then(data => { setUsers(data); setLoading(false); })
      .catch(err => { setError(err.message); setLoading(false); });
  }, []);
  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
This loading/error/data pattern appears in almost every React app. Master it.

Data Fetching: Cancellation with AbortController

audio-player/src/App.jsx, audio-player/src/api/fetchTracks.js
fetchTracks.js
useEffect(() => {
  const controller = new AbortController();

  fetch('/api/users', { signal: controller.signal })
    .then(res => res.json())
    .then(setUsers)
    .catch(err => {
      if (err.name !== 'AbortError') setError(err.message);
    });

  return () => controller.abort();  // Cancel fetch on unmount
}, []);
Without cancellation, unmounted components can still try to setState, causing React warnings and potential memory leaks.
