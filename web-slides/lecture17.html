// Backend: install cors middleware
const cors = require('cors');
app.use(cors({
  origin: 'http://localhost:5173',  // Vite dev server
  credentials: true,                // allow cookies/auth headers
}));
In production, replace the origin with your actual domain. Never use cors() with no options in production.

API Service Layer

habit-tracker/src/api/client.ts

Create a centralized API layer in your React app:

src/services/api.js
const API_BASE = 'http://localhost:3000/api';
export async function fetchWithAuth(endpoint, options = {}) {
  const token = localStorage.getItem('token');
  const res = await fetch(`${API_BASE}${endpoint}`, {
    ...options,
    headers: { 'Content-Type': 'application/json', ...(token && { Authorization: `Bearer ${token}` }), ...options.headers },
  });
  if (!res.ok) {
    const error = await res.json().catch(() => ({}));
    throw new Error(error.message || `HTTP ${res.status}`);
  }
  return res.json();
}

}

The "Test-First, AI-Implement" Pattern

  • 1. You write the tests — this forces you to think about requirements
  • 2. AI implements the code — to pass your tests
  • 3. You review — does the implementation match your intent?
  • 4. You iterate — adjust tests or implementation as needed
workflow
You: Write test → AI: Write code → You: Review → Ship
Tests become your specification language. AI becomes your implementation assistant.

AI Collaboration Best Practices

  • 1. Never submit AI output without understanding it — you must explain every line
  • 2. Use AI for boilerplate, think for yourself on architecture — schema, API design, state structure = yours
  • 3. Write tests before asking AI to code — tests are your spec
  • 4. Compare your solution with AI's — learn from the differences
  • 5. Keep an AI usage log — builds self-awareness about what you know vs. what you delegated
The goal is not to avoid AI. The goal is to use AI as an accelerator while you remain the decision-maker.
