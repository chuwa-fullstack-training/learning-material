Object-Oriented Programming

🏗 Class

A blueprint for creating objects. Defines the shape (properties) and behavior (methods) that all instances will share.

📦 Object

An instance of a class. Each object has its own copy of properties but shares methods via the prototype chain.

🧬 Inheritance

A class can extend another class, inheriting all its properties and methods. Enables code reuse and hierarchy.

🔀 Polymorphism

A subclass can override inherited methods to provide its own specialized behavior.

Back to the Old Days

Before ES6, JavaScript had no class keyword. We used constructor functions with new to mimic class-based OOP.

Built-in classes like Date and Array already followed this pattern. The challenge was creating our own.

built-in constructors

our own — how?

var person2 = new Person();
// How do we define Person?

Constructor Function

  • A regular function used with new to create object instances
  • Convention: capitalize the first letter (Person, not person)
  • Inside, use this to assign instance properties
  • No explicit return needed — new returns the new object automatically
constructors.js
function Person(name, age) {
  this.name = name;
  this.age  = age;
}

const person = new Person('Aaron', 30);
console.log(person.name);  // Aaron
console.log(person.age);   // 30

lecture04 / new-keyword
under the hood

What Does new Actually Do?

① Create

Creates a new, empty object: const obj = {}

② Link

Sets obj.__proto__ to Constructor.prototype, linking the new object to the shared method pool.

③ Execute

Calls the constructor with this = obj. All this.x = … assignments go onto the new object.

④ Return

Returns obj automatically — unless the constructor explicitly returns a different object.

lecture04 / simulate-new
interview classic

Simulate new Step by Step

myNew.js
function myNew(Constructor, ...args) {
  // ① Create empty object
  const obj = {};
  // ② Link __proto__
  Object.setPrototypeOf(obj, Constructor.prototype);
  // ③ Execute constructor
  const result = Constructor.apply(obj, args);
  // ④ Return object
  return result instanceof Object
    ? result : obj;
}
usage
function Person(name) {
  this.name = name;
}
const p = myNew(Person, 'Aaron');
console.log(p.name);              // Aaron
console.log(p instanceof Person);  // true
🎯 Common interview question: implement new by hand. Understand these 4 steps and new will never feel mysterious again.

The this Keyword

this refers to the object that called the function — not where the function was defined. Its value is determined at call time.

  • callName() — called as a plain function; this is undefined (strict) or global
  • obj.callName() — called as a method; this is obj
  • callName.call(obj) — explicit binding; forces this to obj
this.js
function callName() {
  console.log(this.name);
}

const obj = {
  name: 'obj',
  callName,
};

callName();          // undefined
obj.callName();      // 'obj'
callName.call(obj);  // 'obj'

lecture04 / this-binding
five rules

this Binding Rules

1. Implicit

obj.method() — this is the object to the left of the dot.

2. Explicit

fn.call(ctx) / fn.apply(ctx) / fn.bind(ctx) — manually specify this.

3. new Binding

new Fn() — this is the newly created object. Highest priority over implicit/explicit.

4. Lexical (Arrow)

Arrow functions inherit this from their enclosing scope at definition time — it never changes.

5. Global / Default

Standalone call with no context: window in browsers, global in Node, undefined in strict mode.

this Pitfall: Losing Context

❌ Regular function — loses this
broken-timer.js
class Timer {
  constructor() {
    this.seconds = 0;
  }
  start() {
    setInterval(function () {
      this.seconds++;  // ❌ global!
      console.log(this.seconds); // NaN
    }, 1000);
  }
}
✅ Arrow function — lexical this
fixed-timer.js
class Timer {
  constructor() {
    this.seconds = 0;
  }
  start() {
    setInterval(() => {
      this.seconds++;  // ✅ Timer
      console.log(this.seconds); // 1, 2, 3…
    }, 1000);
  }
}
🎯 This is the classic bug in React class components. Once you understand it, seeing .bind(this) in old React code will make perfect sense.

prototype vs __proto__

.prototype .__proto__
Who has it? Functions (constructors) All objects
What is it? Object holding shared methods Points to constructor's .prototype
Purpose Define shared behavior for instances Forms the lookup chain
proto.js
function Person(name) {
  this.name = name;
}
Person.prototype.greet = function() {
  return `Hi, I'm ${this.name}`;
};

const p = new Person('Aaron');

// p.__proto__ IS Person.prototype
p.__proto__ === Person.prototype;  // true

// greet is found via __proto__ chain
p.greet();  // "Hi, I'm Aaron"

The class Syntax

class is syntactic sugar over constructor functions and prototypes. Under the hood it works exactly the same way — it's just cleaner to read.

  • Convention: capitalize the class name (Person)
  • constructor() runs when you call new Person()
  • Methods defined in the class body go onto Person.prototype
  • Classes are not hoisted — unlike function declarations
class.js
class Person {
  constructor(name, age) {
    this.name = name;
    this.age  = age;
  }

  greet() {
    return `Hi, I'm ${this.name}`;
  }
}

const p = new Person('Aaron', 30);
console.log(p.greet());  // Hi, I'm Aaron

lecture04 / static-method
class methods

static Methods

A static method belongs to the class itself, not to any instance. Call it on the class directly.

  • Called as Person.create(…) — not p.create(…)
  • Common use: factory methods, utility helpers, caches
  • this inside a static method refers to the class, not an instance
  • e.g. Array.isArray(), Object.keys(), Math.max() are all static
class.js
class Person {
  constructor(name, age) {
    this.name = name;
    this.age  = age;
  }

  static create(name, age) {
    return new Person(name, age);
  }
}

// Called on the class, not an instance
const p = Person.create('Aaron', 30);

Public & Private Properties

ES2022 introduced private fields using the # prefix. Private fields are strictly inaccessible outside the class — not just a convention.

  • Public properties (this.name) — readable and writable from anywhere
  • Private fields (#age) — only accessible within the class body
  • Accessing p.#age from outside throws a SyntaxError
  • Use getters/setters to expose controlled access to private fields
class_property.js
class Person {
  // private field (ES2022)
  #age;

  constructor(name, age) {
    this.name = name;  // public
    this.#age  = age;   // private
  }

  getAge() {
    return this.#age;  // ok inside
  }
}

const p = new Person('Aaron', 30);
console.log(p.name);     // 'Aaron' ✅
console.log(p.getAge());  // 30 ✅
console.log(p.#age);    // SyntaxError ❌

lecture04 / inheritance

Class Inheritance

Parent class

parent
class Person {
  constructor(name, age) {
    this.name = name;
    this.age  = age;
  }

  sayHello() {
    console.log(
      `Hello, I'm ${this.name}`
    );
  }
}

Child class

child (extends)
class Student
  extends Person {

  constructor(name, age, major) {
    super(name, age);
    this.major = major;
  }
}

const s = new Student(
  'Aaron', 20, 'CS'
);
s.sayHello(); // inherited ✅
Student inherits sayHello() from Person via the prototype chain. Must call super() before accessing this in the child constructor.

lecture04 / super
parent access

The super Keyword

  • super(…args) — calls the parent class constructor
  • Must be called before any this usage in the child constructor
  • super.method() — calls a method on the parent class
  • Useful when overriding a method but still wanting the parent behavior
  • Ensures the superclass is fully initialized before subclass adds its own state
super.js
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a noise.`;
  }
}

class Dog extends Animal {
  constructor(name) {
    super(name);  // ← must come first
    this.type = 'dog';
  }
  speak() {
    return super.speak() + ' Woof!';
  }
}

ES6

Arrow Functions

Arrow functions are a concise function syntax with a key difference: no own this, no arguments, no prototype.

  • No own this — inherits from enclosing scope
  • No arguments object — use rest params instead
  • Cannot be used as a constructor (new throws)
  • Implicit return when body is a single expression
  • Wrap object literals in (): () => ({ key: val })
arrow.js
const add = (a, b) => {
  return a + b;
};

// Implicit return (single expression)
const sum    = (a, b) => a + b;
const square = x => x * x;

// Object literal — wrap in ()
const foo = () => ({ bar: 1 });

this in Arrow Functions

✅ Regular function — own this (implicit binding)
method-regular.js
const obj = {
  name: 'John',
  sayHi: function () {
    console.log(
      `Hi, I'm ${this.name}`
    );
  }
};
obj.sayHi();  // Hi, I'm John ✅
❌ Arrow function — no own this (inherits outer)
method-arrow.js
const obj = {
  name: 'John',
  sayHi: () => {
    console.log(
      `Hi, I'm ${this.name}`
    );
  }
};
obj.sayHi();  // Hi, I'm undefined ❌
Rule of thumb: use regular functions for object methods (need own this); use arrows for callbacks and nested functions (want to inherit outer this).

lecture04 / spread-rest
ES6

Spread / Rest Operators

Spread — expand

spread array
const arr = [1, 2, 3];
const next = [...arr, 4, 5];
// [1, 2, 3, 4, 5]
spread object
const obj = { a: 1, b: 2 };
const next = { ...obj, c: 3 };
// { a: 1, b: 2, c: 3 }

Rest — collect

rest params
function foo(first, ...rest) {
  console.log(first);  // 1
  console.log(rest);   // [2, 3, 4]
}
foo(1, 2, 3, 4);

Rest collects remaining arguments into a real array — unlike the old arguments object.

Destructuring

Array destructuring
array
const arr = [1, 2, 3];
const [a, b, c] = arr;

// skip elements
const [x, , z] = arr;  // z=3

// with default
const [p = 0, q = 0] = [];  // p=0, q=0
Object destructuring
object
const obj = { a: 1, b: 2 };
const { a, b } = obj;

// rename
const { a: alpha } = obj;  // alpha=1

// with default
const { c = 99 } = obj;  // c=99
You'll use object destructuring constantly in React: const { name, age } = props and const [count, setCount] = useState(0).

lecture04 / template-literals
ES6

Template Literals

Use backticks ` ` instead of quotes. Embed any expression with ${…}. Multi-line strings work naturally.

  • Embed variables, function calls, or any expression
  • No more string concatenation with +
  • Supports multi-line strings without \n
  • Tagged templates allow custom string processing (advanced)
template-literals.js
const name = 'John';
const age  = 30;

// Old way
"Hi, I'm " + name + " and I'm "
  + age + " years old";

// ES6 way
`Hi, I'm ${name} and I'm ${age} years old`;

// Expression inside ${}
`Result: ${2 + 2}`;   // "Result: 4"
`Admin: ${age >= 18 ? 'yes' : 'no'}`;

lecture04 / optional-chaining
ES2020

Optional Chaining ?.

Safely access deeply nested properties. Returns undefined instead of throwing if any step in the chain is null or undefined.

  • Works on property access: a?.b?.c
  • Works on method calls: obj?.method?.()
  • Works on array indexing: arr?.[0]
  • Short-circuits: if left side is null/undefined, stops and returns undefined without evaluating right side
optional-chaining.js
const user = {
  profile: { address: { city: 'Toronto' } }
};

// ❌ Before: verbose null checks
const city = user
  && user.profile
  && user.profile.address
  && user.profile.address.city;

// ✅ After: clean and safe
const city2 =
  user?.profile?.address?.city;  // 'Toronto'
const zip =
  user?.profile?.address?.zip;   // undefined (no error)

lecture04 / nullish-coalescing
ES2020

Nullish Coalescing ??

Returns the right-hand value only when the left is null or undefined — unlike || which triggers on any falsy value (0, '', false).

  • || — default if falsy (0, '', false, null, undefined)
  • ?? — default only if null or undefined
  • Use ?? when 0 or '' are valid values
nullish.js
const count = 0;
console.log(count || 10);   // 10  ❌ 0 is falsy!
console.log(count ?? 10);   // 0   ✅ only null/undef

const name = '';
console.log(name || 'Anonymous');  // 'Anonymous' ❌
console.log(name ?? 'Anonymous');  // ''           ✅

// Common combo with optional chaining
const city =
  user?.profile?.city ?? 'Unknown';
🎯 ?. and ?? are the two most frequently used syntax features in modern JS projects. You'll see them in every React codebase.

lecture04 / shallow-deep-copy

Shallow vs Deep Copy

❌ Reference (no copy)

shared reference
const obj = { a: 1 };
const copy = obj;
copy.a = 99;
console.log(obj.a);  // 99 ❌

Both point to the same object. Mutating one mutates the other.

⚠️ Shallow Copy

spread / Object.assign
const obj = { a: 1, n: {x:1} };
const copy = { ...obj };
copy.a = 99;   // ✅ independent
copy.n.x = 99; // ❌ shared ref!

Top-level is copied; nested objects are still shared references.

✅ Deep Copy

JSON round-trip
const obj = { a: 1, n: {x:1} };
const copy = JSON.parse(
  JSON.stringify(obj)
);
copy.n.x = 99; // ✅ obj.n.x=1

Completely independent clone. Caveat: loses functions, undefined, and circular refs.
