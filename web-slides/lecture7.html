Event Loop in Node.js

  • Node.js is single-threaded — just like the browser's JS thread
  • It uses an event loop to handle concurrency without spawning OS threads per request
  • The event loop itself is implemented by libuv — a C library that also handles file I/O, networking, and timers
You already know this mental model from Lecture 5 — the call stack, a callback queue, and a loop that moves work between them. Node just swaps the browser's Web APIs for libuv.

Building a Web Server

  • A route is a section of code that handles a request for a specific HTTP method + URL path
  • Static website — same file(s) served every time
  • Dynamic website — response built per-request, from code/data
web-server.js
const { url, method } = req;
if (method === 'GET') {
  if (url === '/') {
    res.end('this is the home page');
  } else if (url === '/about') {
    res.end('this is the about page');
  } else {
    res.end('this is the 404 page');
  }
}

sync-vs-async.js
lecture07 / sync-vs-async
why it matters on a server

Sync vs. Async

sync-vs-async.js
// ❌ Synchronous — blocks the ENTIRE server
const data = fs.readFileSync('large-file.json', 'utf-8');
processData(data);

// ✅ Asynchronous — server keeps handling other requests
fs.readFile('large-file.json', 'utf-8', (err, data) => {
  if (err) throw err;
  processData(data);
});

// ✅ Promise-based (modern, recommended)
import { readFile } from 'fs/promises';
const data2 = await readFile('large-file.json', 'utf-8');
In a server, never use sync methods (readFileSync, writeFileSync) — they block the event loop and freeze every other request until they finish.
