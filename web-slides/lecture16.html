Redux Terms

  • Store — single source of truth — the one place holding all app state
  • Action — plain JS object describing what happened ({ type: 'ADD_TODO', payload: '...' })
  • Dispatch — the only way to trigger a state change — sends action to the reducer
  • Reducer — pure function: (state, action) => newState
  • Slice — a collection of reducer logic and actions for one feature

Native Redux: Reducer

counterReducer.js
const initialState = { count: 0 };
function counterReducer(state = initialState, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    case 'DECREMENT':
      return { ...state, count: state.count - 1 };
    default:
      return state;
  }
}
A reducer is a pure function: same input always produces same output, no side effects.

The Problem with Native Redux

Native Redux requires a lot of boilerplate:

  • Action type constants (const INCREMENT = 'INCREMENT')
  • Action creators (const increment = () => ({ type: INCREMENT }))
  • Switch statements in reducers
  • Immutable update patterns ({ ...state, nested: { ...state.nested } })
  • Separate files for actions, reducers, types
This is why Redux Toolkit (RTK) was created.

Redux Toolkit: createSlice

redux-rtk.js, habit-tracker/src/store/habitsSlice.js
counterSlice.js
import { createSlice, configureStore } from '@reduxjs/toolkit';
const counterSlice = createSlice({
  name: 'counter',
  initialState: { count: 0 },
  reducers: {
    increment: (state) => { state.count += 1; },     // "mutating" is OK with Immer
    decrement: (state) => { state.count -= 1; },
    addBy: (state, action) => { state.count += action.payload; },
  },
});
export const { increment, decrement, addBy } = counterSlice.actions;
const store = configureStore({ reducer: { counter: counterSlice.reducer } });
RTK uses Immer under the hood. Live demo: habitsSlice.js's checkIn does habit.checkIns.push(...) directly — Immer only creates a new object for the changed habit, so unaffected siblings keep their reference, which is why React.memo on HabitListItem still works.

Async Actions: createAsyncThunk

habit-tracker/src/store/habitsSlice.js, useEnsureHabitsLoaded.js
usersSlice.js
import { createAsyncThunk } from '@reduxjs/toolkit';
export const fetchUsers = createAsyncThunk('users/fetch', async () => {
  const response = await fetch('/api/users'); return response.json();
});
const usersSlice = createSlice({
  name: 'users', initialState: { items: [], loading: false, error: null },
  extraReducers: (builder) => {
    builder.addCase(fetchUsers.pending, (state) => { state.loading = true; })
      .addCase(fetchUsers.fulfilled, (state, action) => { state.loading = false; state.items = action.payload; })
      .addCase(fetchUsers.rejected, (state, action) => { state.loading = false; state.error = action.error.message; });
  },
});
Live demo: fetchHabits is the same pending/fulfilled/rejected pattern. useEnsureHabitsLoaded.js is a small custom Hook both HabitsLayout and StatsPage call on mount — whichever route mounts first dispatches the thunk; the other just reads the cached status.

ThemeContext.jsx
import { createContext, useContext, useState } from 'react';
const ThemeContext = createContext('light');
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  return <ThemeContext.Provider value={{ theme, setTheme }}>{children}</ThemeContext.Provider>;
}
function ThemedButton() {
  const { theme, setTheme } = useContext(ThemeContext);
  return <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>Theme: {theme}</button>;
}

useReducer — Redux-lite in React

Counter.jsx
function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    default: throw new Error(`Unknown action: ${action.type}`);
  }
}
function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return <div>
    <p>{state.count}</p>
    <button onClick={() => dispatch({ type: 'increment' })}>+1</button>
  </div>;
}
useReducer + Context = a lightweight Redux alternative for medium-complexity state.

When to Use What?

Local component state (form input, toggle)useState
Shared state across 2-3 nearby componentsLift state up + props

Modern Alternatives

Zustand — Minimal Global State

store.js
import { create } from 'zustand';
const useStore = create((set) => ({
  count: 0,
  increment: () => set((s) => ({ count: s.count + 1 })),
}));
function Counter() {
  const { count, increment } = useStore();
  return <button onClick={increment}>{count}</button>;
}

TanStack Query — Server State

  • Handles fetching, caching, synchronization, and background updates
  • Replaces most Redux usage for API data
  • useQuery, useMutation, automatic refetching
You don't need to learn these now — just know they exist for future reference.
