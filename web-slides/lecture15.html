Why Routing in a SPA?

  • SPA = one HTML file, JavaScript handles all page transitions
  • Without routing: all content on one URL, no back button, no bookmarks
  • With routing: different URLs for different pages, browser history works

Navigation: Link & useNavigate

habit-tracker/src/components/Navbar.jsx
NavBar.jsx
import { Link, useNavigate } from 'react-router-dom';
function NavBar() {
  const navigate = useNavigate();
  const handleLogout = () => { logout(); navigate('/login'); }; // programmatic nav
  return <nav>
    <Link to="/">Home</Link>  {/* declarative */}
    <button onClick={handleLogout}>Logout</button>
  </nav>;
}
Link renders an <a> tag that doesn't reload the page. Use useNavigate for programmatic redirects.

useSearchParams — URL State

habit-tracker/src/pages/HabitsListPage.jsx
ProductList.jsx
import { useSearchParams } from 'react-router-dom';
function ProductList() {
  const [searchParams, setSearchParams] = useSearchParams();
  const page = Number(searchParams.get('page')) || 1;
  const sort = searchParams.get('sort') || 'name';
  return <select value={sort} onChange={e => setSearchParams({ page: 1, sort: e.target.value })}>
    <option value="name">Name</option>
    <option value="price">Price</option>
  </select>;
}
URL params are shareable — users can bookmark /products?page=2&sort=price and get the same view.

Protected Routes

habit-tracker/src/auth/ProtectedRoute.jsx
ProtectedRoute.jsx
function ProtectedRoute({ children }) {
  const token = localStorage.getItem('token');
  if (!token) {
    return <Navigate to="/login" replace />;
  }
  return children;
}
// Usage
<Routes>
  <Route path="/login" element={<Login />} />
  <Route path="/dashboard" element={
    <ProtectedRoute><Dashboard /></ProtectedRoute>
  } />
</Routes>
Live demo: App B's ProtectedRoute remembers location.state.from and redirects back after login — try visiting /habits/h1 while logged out. The token is still a mock string (no real backend until L17) — the redirect-back mechanics are real, the auth itself isn't yet.

Code Splitting with React.lazy

habit-tracker/src/App.jsx

Without code splitting, all JavaScript loads upfront. With lazy loading, routes load on demand:

App.jsx
import { lazy, Suspense } from 'react';
const Dashboard = lazy(() => import('./pages/Dashboard'));
function App() {
  return <Suspense fallback={<p>Loading...</p}>
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/dashboard" element={<Dashboard />} />
    </Routes>
  </Suspense>;
}
Live demo: StatsPage is loaded via lazy(() => import('./pages/StatsPage')). Run npm run build and check the output — it ships as its own chunk, separate from the main bundle.

React.memo

habit-tracker/src/components/HabitListItem.jsx
ExpensiveList.jsx
const ExpensiveList = React.memo(function ExpensiveList({ items }) {
  console.log('Rendering ExpensiveList');
  return <ul>{items.map(i => <li key={i.id}>{i.name}</li>)}</ul>;
});
function Parent() {
  const [count, setCount] = useState(0); const items = [{ id: 1, name: 'A' }, { id: 2, name: 'B' }];
  return <div>
    <button onClick={() => setCount(c => c + 1)}>Count: {count}</button> <ExpensiveList items={items} />
  </div>; {/* ExpensiveList won't re-render on count change */}
}
React.memo does a shallow comparison of props. Live demo: click "Check in" on one habit — only that habit's render log fires. This only works because handleCheckIn updates state immutably, keeping unaffected habit objects at the same reference — memo compares by reference, not value.

When to Optimize (and When Not To)

Don't optimize prematurely. Use these tools only when you have:

  • 1. Measured a problem — use React DevTools Profiler
  • 2. Identified the bottleneck — which component re-renders too often?
  • 3. Applied the right fix — memo, useMemo, or useCallback
❌ PREMATURE
optimize.md
"I'll wrap everything in React.memo just in case"
✅ EVIDENCE-BASED
optimize.md
"The list re-renders on every keystroke —
memo + useCallback fixes it"
Performance optimization adds complexity. Only add it when you have evidence of a problem.
