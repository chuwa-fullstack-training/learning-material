4 Ways to Define a Function

📝 Function Declaration

declaration
function name(param1, param2) {
  // statements
}

Hoisted to top of scope. Can be called before its definition.

📌 Function Expression

expression
var name = function(param) {
  // statements
};

Not hoisted. The variable is hoisted but not the value.

🏗️ Function Constructor

constructor (rarely used)
var name = new Function(
  'a', 'b', 'return a+b'
);

Creates functions from strings at runtime. Avoid in practice.

⚡ Arrow Function (ES6)

arrow
const name = (param) => {
  // statements
};

Concise syntax. Does not have its own this.

Function Hoisting

Declarations are moved to the top of their scope at compile time. Only declarations are hoisted — not initializations.

  • function foo() → fully hoisted, callable anywhere in scope
  • var fun = function() → variable is hoisted as undefined, calling it before the assignment throws
hoisting.js
foo();  // ✅ "foo"
fun();  // ❌ TypeError

function foo() {
  console.log('foo');
}

var fun = function () {
  console.log('fun');
};

Function Scope & Variable Masking

Each function creates a new scope. A variable declared inside a function with the same name as an outer variable shadows (masks) the outer one within that function.

  • The inner x is a new, independent variable
  • The outer x is unchanged after foo() returns
  • This is the foundation of closure — inner scopes retain access to outer scopes
scope.js
var x = 1;

function foo() {
  var x = 2;            // new x in foo's scope
  console.log(x);       // 2
}

console.log(x);         // 1

Function Invocation Patterns

1. Function Invocation

Direct call: foo(). In non-strict mode, this refers to the global object.

2. Method Invocation

obj.method(). this refers to the object before the dot. Covered in depth in Lecture 4.

3. Constructor Invocation

Preceded by new: creates a new object, sets this to the new instance, returns it implicitly.

4. Indirect Invocation

fn.call(ctx, ...args) and fn.apply(ctx, [args]) — manually set this and arguments.

Value vs Reference

✅ Primitive → passed by value
number, string, boolean, null, undefined
let a = 10;

function change(x) {
  x = 99;  // modifies local copy
}

change(a);
console.log(a);  // still 10
⚠️ Object → passed by reference
object, array, function
let obj = { n: 10 };

function change(o) {
  o.n = 99;  // mutates original!
}

change(obj);
console.log(obj.n);  // 99 !

lecture03 / options-pattern

Using Object Properties as Arguments

When a function has many optional parameters, pass a single options object instead. Callers only specify what they need.

  • Named parameters → self-documenting call sites
  • Order of properties doesn't matter
  • Easy to extend with new options without breaking callers
  • ES6 destructuring makes this even cleaner: function foo({ name='x', age=0 })
options pattern
function foo(options) {
  var name = options.name || 'default';
  var age  = options.age  || 0;
  console.log(name, age);
}

// Only need name
foo({ name: 'John', age: 20 });
foo({ name: 'John' });  // age defaults to 0

What is a Closure?

A closure is a function that retains access to its parent scope, even after the parent function has returned.

  • The inner function "closes over" the outer variable
  • count lives in makeCounter's scope, but survives after makeCounter returns
  • Each call to makeCounter() creates a fresh, independent closure
closure.js
function makeCounter() {
  let count = 0;           // outer variable
  return function () {
    return ++count;       // closed over
  };
}

const counter = makeCounter();
console.log(counter());    // 1
console.log(counter());    // 2
console.log(counter());    // 3

Closure Pitfall: for + var

❌ Problem — all callbacks print 3
pitfall.js
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 1000);
}
// Output: 3, 3, 3  (not 0, 1, 2!)
Why? var is function-scoped — all three callbacks share the same i. By the time they run, the loop has finished and i === 3.
✅ Fix 1 — use let (block-scoped)
fix-let.js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
// Output: 0, 1, 2 ✅
✅ Fix 2 — IIFE captures each value
fix-iife.js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j), 1000);
  })(i);
}
// Output: 0, 1, 2 ✅

Closure in Practice: debounce

The closure keeps timer private, shared across all calls to the returned function — this is what makes debouncing work.

  • timer is "remembered" by the returned function
  • Each call clears the previous timeout
  • The wrapped function only fires after delay ms of silence
🎯 This is the most common real-world closure application. You will use debounce repeatedly when handling search inputs in React. Understand it deeply.
closure-practical.js
function debounce(fn, delay) {
  let timer = null;  // closed over
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(
      () => fn.apply(this, args),
      delay
    );
  };
}

const handleInput = debounce((value) => {
  console.log('Searching:', value);
}, 300);

IIFE — Immediately Invoked Function Expression

An IIFE is a function that runs immediately after it is defined. The outer parentheses make the parser treat it as an expression; the trailing () invokes it.

  • Creates an isolated scope — variables inside do not pollute global
  • The classic pre-ES6 module pattern
  • Still appears in legacy code and bundler output — know how to read it
Today: use ES modules (import/export) instead of IIFE for isolation. But the pattern underpins the closure pitfall fix from the previous slide.
iife.js
(function () {
  var x = 1;
  console.log(x);  // 1
})();

// x is NOT accessible here
console.log(typeof x);  // "undefined"

// Arrow function IIFE (modern)
(() => {
  const secret = 'scoped';
})();

What is Functional Programming?

A programming paradigm where programs are constructed by composing pure functions, avoiding shared state and mutable data. It is declarative — you express what you want, not how to get it.

Imperative (how)

let total = 0;
for (let i = 0; i < arr.length; i++)
  total += arr[i];

Declarative (what)

const total = arr.reduce(
  (sum, n) => sum + n, 0
);

Key Concepts

Pure Functions

Same input → same output. No side effects. Covered next slide.

Referential Transparency

A pure function call can always be replaced by its return value without changing program behavior.

Immutability

Never mutate existing data — return new values. Prevents unintended side effects across references.

Higher-Order Functions

Functions that take functions as arguments or return functions. The building block of FP.

Currying

Transform a multi-argument function into a series of single-argument functions.

Function Composition

Chain small, focused functions together to build complex behavior from simple parts.

Pure Functions

✅ Pure
same input → same output, no side effects
function add(a, b) {
  return a + b;
}

// Always safe to call:
add(2, 3);  // always 5
add(2, 3);  // always 5
❌ Impure — side effect (mutates external state)
depends on / modifies external state
let total = 0;

function addToTotal(value) {
  total += value;  // ← side effect
  return total;
}

// Result changes each call:
addToTotal(5);   // 5
addToTotal(5);   // 10 !
Why does this matter? Pure functions are predictable, easy to test, and safe to cache. React's component rendering is built on this principle — render the same props, get the same UI.

Immutability

Never modify existing data structures — create new ones with the changes applied. This prevents shared-reference bugs and makes state changes traceable.

❌ Mutation — modifies original
mutable.js
const arr = [1, 2, 3];
arr.push(4);     // mutates arr!

console.log(arr);  // [1, 2, 3, 4]
// original is changed forever
✅ Immutable — returns new array
immutable.js
const arr = [1, 2, 3];
const newArr = arr.concat(4);

console.log(arr);     // [1, 2, 3]  ← unchanged
console.log(newArr);  // [1, 2, 3, 4]

lecture03 / higher-order-functions
HOF

Higher-Order Functions

A function that takes one or more functions as arguments, or returns a function as its result.

  • Enables abstraction over actions, not just values
  • map, filter, reduce, sort are all HOFs built into JavaScript
  • debounce from the previous slide is a HOF that returns a function
  • React event handlers and hooks accept HOFs extensively
higher-order.js
function add(a, b) {
  return a + b;
}

// operate() is the HOF:
// it takes a function as an argument
function operate(a, b, func) {
  return func(a, b);
}

console.log(operate(1, 2, add));  // 3
console.log(operate(4, 5, (a,b) => a*b)); // 20

lecture03 / currying
partial application

Currying

Transform a function with multiple arguments into a series of functions, each taking one argument and returning the next function in the chain.

  • Enables partial application — pre-fill some arguments, defer the rest
  • Creates reusable, specialized functions from general ones
  • e.g. const double = multiply(2) — a specialized multiplier
Currying is named after mathematician Haskell Curry. Many FP libraries (lodash, Ramda) include a curry() utility.
currying.js
// Regular (non-curried)
function multiply(a, b) {
  return a * b;
}

// Curried version
function curriedMultiply(a) {
  return function(b) {
    return a * b;       // closes over a
  };
}

const double = curriedMultiply(2);
const triple = curriedMultiply(3);

double(5);   // 10
triple(5);   // 15

map, filter, and reduce

map

[1,2,3].map(x => x * 2)
// [2, 4, 6]

Transform each element. Returns a new array of the same length.

filter

[1,2,3,4].filter(x => x % 2 === 0)
// [2, 4]

Keep elements where the predicate returns true. Returns a subset.

reduce

[1,2,3].reduce(
  (acc, n) => acc + n, 0
)
// 6

Accumulate elements into a single value. The most powerful — can implement map and filter.

See map-filter-reduce.js in the sample code for exercises on each. These three are the workhorse of React data processing.

Chaining: Real-World Data Pipeline

Chain filter → map → reduce to process arrays declaratively, without any intermediate variables or mutation.

  • filter — select Engineering employees
  • map — apply 10% raise (new objects, immutable)
  • reduce — sum all salaries to a total
🎯 filter → map → reduce is the classic data processing trio. You will use this pattern extensively when handling API response data in React.
pipeline.js
const employees = [
  { name: 'Zhang', salary: 8000, dept: 'Engineering' },
  { name: 'Li',   salary: 6000, dept: 'Marketing' },
  { name: 'Wang',  salary: 9000, dept: 'Engineering' },
];

const result = employees
  // step 1: keep Engineering only
  .filter(e => e.dept === 'Engineering')
  // step 2: 10% raise, new object
  .map(e => ({ ...e, salary: e.salary * 1.1 }))
  // step 3: sum salaries
  .reduce((sum, e) => sum + e.salary, 0);

console.log(result);  // 18700
