Dynamic Site — SSR

  • app.set('view engine', ...) picks the template engine
  • res.render() fills a template with data and sends real HTML
  • Same page, different content — depends on what's passed in
dynamic-site.js

app.set('views', './views');

app.get('/', (req, res) => {
  res.render('index', {
    title: 'Hey',
    message: 'Hello there!'
  });
});

Params, Query String

req.params — part of the path
GET /users/42
app.get('/users/:userId', (req, res) => {
  res.send(req.params.userId);
}); // '42'
req.query — after the ?
GET /users?role=admin
app.get('/users', (req, res) => {
  res.send(req.query);
}); // { role: 'admin' }
Use params for identifying a resource (which user?), query for filtering/options (which subset, sorted how?).

URL Encoding & Decoding

Translates characters that have special meaning in a URL (like &, ?, space) into a form every browser and server agrees on.

❌ ambiguous — is "encoding" a value or a new param?
raw
https://google.com/search?q=url&encoding
✅ unambiguous — the literal & is escaped
encoded
https://google.com/search?q=url%26encoding
Express (and most frameworks) encode/decode this for you automatically — but it's worth recognizing %XX sequences when debugging a URL.

lecture08 / middleware-execution-flow
order matters

Middleware Execution Flow

middleware.js
// Logger — runs for every request
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next(); // pass to next middleware
});
// Auth — only runs for /api routes
app.use('/api', (req, res, next) => {
  if (!req.headers.authorization) {
    return res.status(401).json({ error: 'Unauthorized' });
  }
  next();
});
// Route handler — the final "middleware"
app.get('/api/users', (req, res) => { res.json(users); });
Forget next() → the request hangs forever. Forget return before res.send() → "headers already sent" errors.

Error Handling Middleware

Express error middleware takes 4 parameters — that's how Express tells it apart from regular middleware.

error-handler.js — must be the LAST app.use
// Error handler — 4 params: (err, req, res, next)
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(err.status || 500).json({ error: err.message });
});

// A route that forwards its error
app.get('/api/users/:id', async (req, res, next) => {
  try {
    const user = await findUser(req.params.id);
    if (!user) return res.status(404).json({ error: 'Not found' });
    res.json(user);
  } catch (err) { next(err); } // forward to error handler
});

Router

  • Router-level middleware works like app-level middleware, bound to an express.Router() instance
  • A router is an isolated instance of middleware and routes — a "mini-app"
  • Every Express app has a built-in app router; custom routers let you organize by resource
routers/user.js
const router = express.Router();

// mounted at /api in route.js
router.get('/users', userController.getAllUsers);
router.get('/users/:id', userController.getUserById);

module.exports = router;
