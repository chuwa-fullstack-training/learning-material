Why Custom Hooks?

When you see repeated patterns across components:

duplicated.jsx
// Component A
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
useEffect(() => { fetch('/api/users').then(...) }, []);

// Component B — same pattern, different URL
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
useEffect(() => { fetch('/api/posts').then(...) }, []);
Custom Hooks let you extract and reuse stateful logic without changing component hierarchy.

Building useFetch

useFetch.js
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);
  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    fetch(url, { signal: controller.signal })
      .then(res => { if (!res.ok) throw new Error(`HTTP ${res.status}`); return res.json(); })
      .then(data => { setData(data); setLoading(false); })
      .catch(err => {
        if (err.name !== 'AbortError') { setError(err.message); setLoading(false); }
      });
    return () => controller.abort();
  }, [url]);
  return { data, loading, error };
}

Using useFetch

consumers.jsx
function UserList() {
  const { data: users, loading, error } = useFetch('/api/users');
  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
function PostList() {
  const { data: posts, loading, error } = useFetch('/api/posts'); // same pattern, different data
}
One Hook, used across many components. Live demo: App A doesn't extract a useFetch — the track-list fetch in App.jsx has only one consumer, so there's nothing to reuse yet. The Hook that does get extracted is useAudioPlayer, pulled straight out of Lecture 13's Player.jsx — it shows the other reason to reach for a custom Hook: not reuse, but organizing stateful logic out of a component so the component only renders.

Building useLocalStorage

useLocalStorage.js
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initialValue;
  });
  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);
  return [value, setValue];
}
// Usage
function Settings() {
  const [theme, setTheme] = useLocalStorage('theme', 'light');
  return <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>Current: {theme}</button>;
}

Building useForm

useForm.js
function useForm(initialValues) {
  const [values, setValues] = useState(initialValues);
  const [errors, setErrors] = useState({});
  const handleChange = (e) => {
    const { name, value } = e.target; setValues(prev => ({ ...prev, [name]: value }));
  };
  const reset = () => setValues(initialValues);
  return { values, errors, setErrors, handleChange, reset };
}
// Usage
function LoginForm() {
  const { values, handleChange } = useForm({ email: '', password: '' });
  return <form>
    <input name="email" value={values.email} onChange={handleChange} />
    <input name="password" value={values.password} onChange={handleChange} />
  </form>;
}

Custom Hook Rules

  • Name must start with use — this tells React to check Hook rules
  • Can call other Hooks (useState, useEffect, other custom Hooks)
  • Can return anything: values, arrays, objects, functions
  • Each component using a Hook gets its own copy of state
❌ NOT A HOOK
rules.jsx
// no "use" prefix
function fetchData(url) { /* uses useState inside */ }
✅ CLEARLY A HOOK
rules.jsx
function useFetchData(url) { /* uses useState inside */ }

Component Composition: children

audio-player/src/components/PlayerShell.jsx, Player.jsx

Components can nest other components:

Card.jsx
function Card({ title, children }) {
  return <div className="card">
    <h2>{title}</h2>
    <div className="card-body">{children}</div>
  </div>;
}
// Usage — anything can go inside Card
<Card title="User Profile">
  <Avatar src={user.avatar} /> <p>{user.bio}</p>
</Card>
Think of children as a "slot." Live demo: PlayerShell is this exact pattern — it renders <div className="player">{children}</div> and knows nothing about audio. Player.jsx fills the slot with AlbumArt, TrackInfo, PlayerControls.

Composition vs. Inheritance

React strongly favors composition over inheritance:

❌ INHERITANCE (don't do this)
SpecialButton.jsx
class SpecialButton extends Button { ... }
✅ COMPOSITION
SpecialButton.jsx
function SpecialButton(props) {
  return <Button className="special" {...props} />;
}
// composition with children
function Dialog({ title, children }) {
  return (
    <div className="dialog">
      <h2>{title}</h2>
      {children}
    </div>
  );
}
At Meta, thousands of React components — none use inheritance. Composition handles every use case.

Error Boundary

audio-player/src/components/PlayerErrorBoundary.jsx

Error Boundaries catch JavaScript errors in their child component tree and display a fallback UI.

ErrorBoundary.jsx
class ErrorBoundary extends React.Component {
  constructor(props) { super(props); this.state = { hasError: false, error: null }; }
  static getDerivedStateFromError(error) { return { hasError: true, error }; }
  componentDidCatch(error, errorInfo) { console.error('caught:', error, errorInfo); } // report
  render() {
    if (this.state.hasError) return <h2>Something went wrong: {this.state.error?.message}</h2>;
    return this.props.children;
  }
}
Error Boundaries must be class components — this is one of the few remaining class component use cases.

Using Error Boundaries

App.jsx
function App() {
  return <ErrorBoundary>
    <Header />
    <ErrorBoundary>
      <MainContent />
    </ErrorBoundary>
    <Footer />
  </ErrorBoundary>;
}

What Error Boundaries catch:

rendering errors, lifecycle errors, constructor errors

What they don't catch:

event handlers, async code, server-side rendering, errors in the boundary itself

Live demo: select "Corrupted Entry (demo)" — its data is intentionally missing tags, which crashes TrackInfo during render. PlayerErrorBoundary catches it and shows a fallback instead of a blank screen. A broken audioUrl (404) does not trigger this boundary — that's a resource load error, not a render error.
Wrap Error Boundaries around independent sections of your app — a sidebar crash shouldn't take down the whole page.
